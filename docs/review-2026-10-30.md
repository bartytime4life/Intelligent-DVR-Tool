# Full review — October 30, 2026

Baseline: `main` at [`5f11794`](https://github.com/bartytime4life/Intelligent-DVR-Tool/commit/5f11794cc91f1a37379aaad85b2de79b88a73c03) (PR #42).
Fixes merged as PR #45 ([`cd33e38`](https://github.com/bartytime4life/Intelligent-DVR-Tool/commit/cd33e380a5bef22f688224109ef8e887005d9cfe))
and PR #46 ([`11f358c`](https://github.com/bartytime4life/Intelligent-DVR-Tool/commit/11f358c6d94eea4f6fb2dc728a2ef8b428caa106)).
Test evidence is in the [verification record](verification/review-fixes-2026-10-30/README.md).

The review covered the browser workspaces, the facility editor and the Python
edge service. It combined a code read of every source area, the full Node, Python
and browser suites, and a walkthrough of each workspace in a desktop and a 375 px
browser. Every finding was checked against the code before it was fixed. This is
a defect and usability review, not recognition-quality, device or capacity
qualification.

## Findings and what changed

| Area | Found | Fixed in |
| --- | --- | --- |
| Monitor, Recognition, Events, Zones, System | 21 (1 high, 8 medium, 12 low), plus visual issues from the walkthrough | PR #45 |
| Facility editor | 20 (2 high, 11 medium, 7 low) and one invented-geometry detail | PR #45 |
| Local service, recorder and workers | 20 (1 high, 9 medium, 10 low) | PR #45 |
| Windows launchers always showing as modified | 1 | PR #46 |

**Review data and continuity**
- Unreadable saved reviews, rules or machine setup are backed up before anything
  replaces them, and can be downloaded. Before, the first change overwrote them.
- A second open tab's newer saves are adopted instead of overwritten.
- Zones always edits the saved rule for the selected plan, including direct links
  and Back/Forward; saving can no longer write one plan's rule into another slot.
- Leaving the Facility workspace with unsaved edits asks first.
- A finished analysis no longer replaces a different loaded review without asking.

**Interface**
- Dialogs close only when a press starts and ends on the backdrop, return focus to
  the opener and have accessible names. Disabled buttons look disabled. Empty
  camera tiles, Events search focus and low-contrast labels are readable.
- The Inter font is bundled; the app makes no Google Fonts request.
- Each workspace has an error boundary instead of a blank page.

**Facility editor**
- Cameras mounted just inside a facade keep their estimated coverage, and coverage
  is drawn for every enabled camera instead of the first twelve.
- Moving or rotating a building carries its rooms, openings, paths, stairs, zones,
  cameras and labels. Drawn outlines snap within 30 cm of a wall.
- Saved facilities can be removed; dimension fields apply on Enter or blur and no
  longer drift between metres and feet; undo has redo and keyboard shortcuts.
- Keeping imported buildings at their map positions re-projects every point
  through the old and new origins (the Codex review on PR #45 caught a uniform
  shift that moved items east at high latitudes).

**Local service**
- Windows: atomic replacements retry during sharing violations, static files use
  fixed content types, and the CPU model loads from verified bytes, so non-ASCII
  profile paths work. `edge/inference.py` stays byte-identical because the
  [durable-overload evidence](verification/durable-overload-2026-10-28/README.md)
  pins it; the CPU loader moved to `edge/cpu_backend.py`.
- Requests run on a bounded thread pool, downloads stream after locks are
  released, and refused uploads still deliver their JSON reason.
- On Linux, API requests from another account on the same computer are refused.
- Worker CPU limits fit multi-threaded work, workers end with the service, and the
  recorder counts scratch space once and evicts its own oldest segments when the
  disk reserve is low. Import locks are released by the OS after a crash.

## Missed opportunities now in review

The review also listed improvements that make the tool more useful day to day.
The owner approved a four-part plan on October 31 and chose two product rules:
thumbnails stay in this browser's IndexedDB, and LAN-recorder observations reach
Events only through an explicit **Send to Events** per segment. These pull requests
are open and not yet part of `main`; each one documents its own behavior.

| PR | Adds |
| --- | --- |
| [#47 Review workflow](https://github.com/bartytime4life/Intelligent-DVR-Tool/pull/47) | Local stills per observation, keyboard review with auto-advance, camera/recording filters, sorting, CSV export and bulk dismiss with Undo; LAN segment counts and explicit send; DVR frame age; webcam hot-plug |
| [#48 Zones on real images](https://github.com/bartytime4life/Intelligent-DVR-Tool/pull/48) | Zones drawn on a camera still in full-frame coordinates; an analyzer-ready rule export (the previous export could not be loaded by the analyzer) |
| [#49 Camera planning](https://github.com/bartytime4life/Intelligent-DVR-Tool/pull/49) | Pixel-density (detect/observe/recognize/identify) distances, coverage and overlap per zone and route, blind-spot overlay, camera drag/rotate, printable installer sheet |
| [#50 Local service robustness](https://github.com/bartytime4life/Intelligent-DVR-Tool/pull/50) | Recorder crash fix for analyzer failure files, specific failure causes, a credential-free diagnostic log, model reuse across segments, timing-drift and eviction status, streaming source hashing, hash-pinned installs |

PR #48 is stacked on #47 and merges after it.

## Open follow-ups

- A long-lived analysis worker: per-process CPU-time limits accumulate, so it needs
  recycling and a pipe protocol before it can replace one process per segment.
- Waiting on worker exit instead of the 0.1 s poll in `Jobs._run`.
- Rule timing still assumes a constant frame rate. The open PRs warn when a LAN
  segment's sampled times may lag real time by more than 0.5 s instead of changing
  the timing contract shared by the analyzer, evaluator and browser.
- Pressing **Center camera** right after switching to 2D can leave the map tilted.
- Hash-pinned Python installs (PR #50) need their first Windows CI run.
- Physical webcam hot-plug, physical DVR stills and touch dragging on real devices
  are untested.

Recognition quality, live tracking, physical-device compatibility and 100-camera
capacity remain unqualified.
